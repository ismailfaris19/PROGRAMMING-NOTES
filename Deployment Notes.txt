////// Steps to deploy an Angular + Node.js application using a CI/CD pipeline //////

@ 1. Understand the CI/CD workflow:

    > For an Angular frontend with a Node.js and Express.js backend, a CI/CD pipeline automates code validation, testing, building, and deployment whenever developers push changes to a Git repository.

    > I'll explain the process using GitHub + GitHub Actions + Docker + a cloud server as an example. The same concepts apply to Jenkins, Azure DevOps, GitLab CI/CD, and AWS.

    > Continuous Integration (CI): Automatically checks code quality and runs tests.

    > Continuous Delivery/Deployment (CD): Packages the application and prepares or automatically releases it to the target environment.

    > FLOW DIAGRAM:

        1. Developer pushes code
        GitHub repository · feature branch / main
            ↓
        2. CI pipeline starts
        Install dependencies · lint · unit tests
            ↓
        3. Build and package
        Angular production build · Node.js checks · Docker image
            ↓
        4. Validate and publish
        Integration tests · security checks · image registry
            ↓
        5. Deploy to server
        Start/update services · health check · rollback if needed


@ 2. Prepare the application:

    > Your actual structure may differ. If frontend and backend are in separate repositories, the pipeline can be configured separately for each.

        my-application/
        ├── frontend/              # Angular application
        │   ├── src/
        │   ├── package.json
        │   └── angular.json
        ├── backend/                # Node.js + Express API
        │   ├── src/
        │   ├── package.json
        │   └── server.js
        ├── Dockerfile.frontend
        ├── Dockerfile.backend
        └── .github/
            └── workflows/
                └── ci-cd.yml


@ 3. Configure npm scripts:

    > Ensure both projects have the scripts required by the pipeline.

        =>  Angular — frontend/package.json
            {
                "scripts": {
                    "build": "ng build",
                    "test:ci": "ng test --watch=false --browsers=ChromeHeadless"
                }
            }


        =>  Node.js — backend/package.json
            {
                "scripts": {
                    "start": "node server.js",
                    "test": "jest"
                }
            }


    > These are examples. Use your existing scripts and testing framework; for Angular Karma tests, make sure the CI environment has a compatible headless browser available.


@ 4. Create the CI/CD workflow:
    
    > Create this file in the repository:
        >> .github/workflows/ci-cd.yml

    > The following example installs dependencies, runs tests, builds Angular, and verifies the Node.js application. It assumes the frontend and backend are in separate directories and each has its own package-lock.json.

    > CODE SNIPPET:

        name: Angular Node CI

        on:
            pull_request:
                branches: [main]
            push:
                branches: [main]

        jobs:
            test-and-build:
                runs-on: ubuntu-latest

                steps:
                      - name: Checkout code
                        uses: actions/checkout@v4

                      - name: Set up Node.js
                        uses: actions/setup-node@v4
                        with:
                            node-version: '22'
                            cache: npm
                            cache-dependency-path: |
                                frontend/package-lock.json
                                backend/package-lock.json

                      - name: Install frontend dependencies
                        working-directory: frontend
                        run: npm ci

                      - name: Run Angular tests
                        working-directory: frontend
                        run: npm run test:ci

                      - name: Build Angular
                        working-directory: frontend
                        run: npm run build

                      - name: Install backend dependencies
                        working-directory: backend
                        run: npm ci

                      - name: Run backend tests
                        working-directory: backend
                        run: npm test

                      - name: Verify backend starts
                        working-directory: backend
                        run: npm run build --if-present

    > This is a CI example, not a complete deployment workflow. Choose a Node.js version compatible with your Angular version and dependencies. The workflow uses GitHub Actions to run the same installation, build, and test commands you use locally.


@ 5. Build the production application:

    > Angular's production build creates optimized static files, while the Node.js backend runs as a server process.

        # Angular frontend
        cd frontend
        npm ci
        npm run build

        # Node.js backend
        cd ../backend
        npm ci
        npm test


    > Angular's output normally goes into dist/, with the exact path determined by angular.json. 
    
    > The frontend can be served through Nginx or a static hosting service; the backend can run on a virtual machine, container platform, or managed application service.


@ 6. Deploy the frontend and backend:

    > Choose a hosting strategy based on your infrastructure.

        Layer             | Deployment option                     | What gets deployed
        Angular           | Nginx, static hosting, CDN            | Production build files
        Node.js + Express | VM, Docker, container service         | Backend application
        Database          | Managed database or private server    | Schema and data, managed separately
        CI/CD             | GitHub Actions, Jenkins, Azure DevOps | Automated build and deployment steps

    > A typical deployment flow is:
        1. Build and test both applications.
        2. Package the frontend and backend as artifacts or Docker images.
        3. Publish artifacts or images to storage or a container registry.
        4. Deploy to the staging environment.
        5. Run smoke tests and health checks.
        6. Deploy to production only when the required checks and approvals pass.

    > For a container-based deployment, Docker's Angular guide demonstrates a multi-stage build that compiles Angular with Node.js and serves the resulting static assets with Nginx.


@ 7. Configure environment variables and secrets:
    
    > Store deployment credentials in GitHub rather than directly in source code.

    > Navigate to GitHub → Repository → Settings → Secrets and variables → Actions.

    > Examples of secrets:
        DEPLOY_HOST
        DEPLOY_USER
        DEPLOY_SSH_KEY
        DATABASE_URL
        API_SECRET

    > Use only the secrets required by your deployment platform. Configure production environment variables on the server or hosting platform, and never expose backend secrets in Angular environment files because frontend values are delivered to browsers.


@ 8. Verify the deployment:

    > After deployment, verify the following:
        - Angular application loads correctly.
        - Angular routes work after refreshing a page.
        - Angular API URLs point to the correct backend environment.
        - Express API endpoints respond correctly.
        - Database connectivity works.
        - Authentication, CORS, and environment variables are configured correctly.
        - Logs and health checks show no errors.
        - Rollback is possible if the new release fails.
    
    
@ 9. Choose your CI/CD platform:

    > GitHub Actions: Best if your source code is hosted on GitHub. Workflow files live in the repository.

    > Jenkins: Useful for self-hosted CI/CD infrastructure and customizable pipelines.

    > Azure DevOps: Useful for enterprise repositories, build pipelines, and controlled releases.



////// Steps to host an Angular frontend + Node.js/Express backend application on AWS //////

@ Understand the AWS host workflow:

    > For an Angular frontend + Node.js/Express backend, you can host the application on AWS and automate deployment using a CI/CD pipeline.

    > A good starting architecture is:

        GitHub repository
        Push code or merge a pull request
            ↓
        GitHub Actions
        Install dependencies → test → build → deploy
            ↓
        Angular                 | Node.js / Express
        Amazon S3 + CloudFront  | AWS Elastic Beanstalk
        Frontend hosting        | Backend hosting
            ↓
        Database
        Amazon RDS for MySQL, if your app uses MySQL

    > This is one practical setup: S3 and CloudFront serve the Angular app, Elastic Beanstalk runs the Node.js API, and RDS hosts the database if needed. You can use other AWS services, too.


@ Step 1: Prepare your application:

    > Assume your repository has this structure:

        >>  my-app/
            ├── frontend/          # Angular
            ├── backend/           # Node.js + Express
            └── .github/
                └── workflows/


    > Before deploying, confirm both applications work locally.

        >>  Angular — frontend/:
            npm ci
            npm run build


    > The production build will be generated under dist/ (the exact nested output path depends on your Angular configuration). Angular's official deployment guide explains how to locate and serve the build output. 


        >>  Node.js — backend/: Make sure your package.json has a start command, for example:
            {
                "scripts": {
                    "start": "node server.js"
                }
            }


    > Your Express server must listen on the port provided by the hosting environment:
        >>  const PORT = process.env.PORT || 3000;

            app.listen(PORT, "0.0.0.0", () => {
                console.log(`Server running on port ${PORT}`);
            });


    > Use your actual entry-point filename if it isn't server.js.
