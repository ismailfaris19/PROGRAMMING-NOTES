//////////////////////////////////// ANGULAR LIFECYCLE HOOKS ////////////////////////////////////

@ Angular lifecycle hooks are methods that Angular calls at specific stages of a component/directive's life — from creation → updates → destruction.

@ Angular Hooks:

    > constructor(): It is not an Angular lifecycle hook. It's a TypeScript/JavaScript class constructor. USES: Dependency injection, Basic initialization

    > ngOnChanges(): Called when an Angular input property changes.

    > ngOnInit(): Called once after Angular initializes the component's inputs. USES: API calls, Initial component setup, Initializing data

    > ngDoCheck(): Called during Angular's change-detection cycle. 

    > ngAfterContentInit(): Called once after Angular initializes content projected using <ng-content>.

    > ngAfterContentChecked(): Runs after Angular checks the projected content.

    > ngAfterViewInit(): Called once after Angular initializes the component's view and child views. Because the view needs to exist before you access the element.

    > ngOnDestroy(): Called just before Angular destroys the component. USES: Cleanup subscriptions, Remove event listeners, Clear timers, Cleanup resources

@ Hooks flow: Component Created => constructor() => ngOnChanges()[re-run during updates] => ngOnInit() => ngDoCheck() [re-run during updates] => ngAfterContentInit() => ngAfterContentChecked() => ngOnDestroy() => Component Destroyed


//////////////////////////////////// ANGULAR BINDINGS ////////////////////////////////////

@ Event binding (): Listens for user actions (like a button click, mouse movement, or keypress) and runs a function in your component.

    > (keyup.enter)="saveData($event)"

@ Class binding []: Adds or removes CSS classes dynamically based on a true/false condition.

@ Style binding []: Sets inline CSS styles on an HTML element dynamically.

    > [style.font-size.px]="fontSize", [style.width.px]="200"


//////////////////////////////////// ANGULAR FORMS ////////////////////////////////////

@ In Angular, forms fall into two distinct paradigms: Reactive Forms (model-driven, programmatic control in the TypeScript class) and Template-Driven Forms (directive-driven, configured in the HTML template).

@ Because FormGroup, FormControl, and FormArray inherit from AbstractControl, the following methods apply to both Reactive models and Template-Driven form instances (NgForm / NgModel).

@ Core Control Methods (Shared Across Both Paradigms):

    > setValue(): Sets the value of a control/group. Strict: Requires values for all controls in a group.
        >> this.form.setValue({...})

    > patchValue(): Partially updates values. Ignores missing fields.
        >> this.form.patchValue({...})

    > reset(): Resets the value to initial/null and resets pristine/untouched flags.
        >> this.form.reset()

    > get(): Retrieves a child control by name or dot-delimited path.
        >> this.form.get({...})

    > disable() / enable(): Toggles disabled state and excludes/includes the control from validation & aggregate value.
        >> this.form.get('...')?.disable();

    > setValidators(): Programmatically sets or overwrites sync validators.
        >> this.control.setValidators([...]);

    > clearValidators(): Removes all sync validators from the control.
        >> this.control.clearValidators();

    > updateValueAndValidity(): Re-evaluates value and recalculates validity status (required after changing validators).
        >> this.control.updateValueAndValidity()

    > setErrors(): Manually injects custom validation error(s) onto a control.
        >> this.control.setErrors({ customErr: true });

    > hasError(): Checks if a specific error key exists on the control.
        >> this.control.hasError('required')

    > markAsTouched(): Marks the control as touched (triggers UI validation error displays).
        >> this.form.markAllAsTouched();

    > markAsDirty(): Marks the control as modified by the user.
        >> this.control.markAsDirty();

@ 1. Reactive Forms: Methods & Usage:

    > Reactive Forms (ReactiveFormsModule) manage form state programmatically using Validators, FormBuilder, FormGroup, FormControl, and FormArray.

    > Best For Complex forms, dynamic rows, strict validation.

    > FormBuilder.group() / FormBuilder.control() / FormBuilder.array(): Factory methods to initialize form controls cleanly.

    > FormArray.push() / FormArray.removeAt(): Dynamically adds or removes controls in a collection.

    > FormGroup.addControl() / FormGroup.removeControl(): Dynamically attaches or detaches form fields at runtime.

    > markAllAsTouched(): Recursively marks every nested control as touched (ideal upon submit button click).

    > [formGroup]="userForm": binding the formGroup in DOM form.

    > formControlName="name" / [formControlName]="i": binding static or dynamic formControl to interactive form elements

    > formArrayName="skills": binding the formArray in parent of list of controls.

    > @for (skill of skills.controls; track $index; let i = $index): loop over the formControls in formArray to render it in DOM.

    > [disabled]="userForm.invalid": disable the submit button based on form validation.

    > (ngSubmit)="onSubmit()": event binding for formGroup in DOM.

@ 2. Template-Driven Forms: Methods & Usage:

    > Template-Driven forms (FormsModule) delegate control creation and binding to Angular directives (ngForm, ngModel, ngModelGroup) in the HTML template. The component references them using @ViewChild or template reference variables (#form="ngForm").

    > Best For Simple forms, search bars, single-input models.

    > ngForm.resetForm(): Resets the internal control values and clears submission/dirty state (unlike standard form.reset(), resetForm() prevents validation errors from flashing immediately after submit).

    > ngForm.setValue() / ngForm.form.patchValue(): Updates the form model programmatically via the form property (FormGroup).

    > @ViewChild('loginForm') formRef!: NgForm: Gets a reference to the template-driven form named loginForm so we can access and control the form in the component's TypeScript code.

    > #loginForm="ngForm": Binding the form reference in DOM form.

    > [(ngModel)]="user.username": Binding the object property to access the form element value.

    > #usernameCtrl="ngModel": Label the form control to access and use the elements

    > usernameCtrl.touched / usernameCtrl.invalid: Access the status and value of the form control to make use of it.

    > < ... required email>: Angular email validation directive and the way of mention the Validators in formControl. 

    > [disabled]="loginForm.invalid": disable the submit button based on form validation.

    > populateDefaults(loginForm) / populateDefaults(form: NgForm): Need to pass the form reference in methods to make use of it.

    > (ngSubmit)="onSubmit(loginForm)": event binding for form submit in DOM.


//////////////////////////////////// @defer (DEFERRABLE VIEWS) ////////////////////////////////////

@ @defer (Deferrable Views) is an Angular template feature that enables declarative, component-level lazy loading.

@ With @defer, Angular automatically splits whatever component, directive, pipe, or library is inside the block into a separate JavaScript bundle chunk. The browser downloads and renders that chunk only when a specific trigger occurs.

@ The 4 Sub-Blocks of @defer:

    > @defer: When the trigger condition evaluates to true. Wraps the heavy component to be chunked and lazy-loaded.

    > @placeholder: Immediately on initial page render. Light static markup or skeleton shown while waiting for the trigger.

    > @loading: During bundle download. Shown while the browser fetches the JavaScript bundle over the network.

    > @error: On network failure. Fallback UI if the chunk fails to download (e.g., offline or 404).

@ Triggers are prefixed with on (event-based) or when (expression-based):

    > on viewport: Triggers when the placeholder enters the visible browser viewport (via IntersectionObserver).
        >>  Typical Use Case: Content located below the fold (comments, charts, footers).

    > on interaction(target?): Triggers when the user clicks or presses a key on the placeholder or a designated element reference.
        >>  Typical Use Case: Modals, expandable accordions, tab panels.

    > on hover(target?): Triggers when the cursor moves over the placeholder or element.
        >>  Typical Use Case: Tooltips, popovers, quick-look previews.

    > on idle: Triggers when the browser has free/idle time, start downloading the required code in advance.
        >>  Typical Use Case: Non-critical widgets like feedback widgets or live chat popups.

    > on timer(duration): Triggers after a specified duration (e.g., on timer(5s)). 
        >>  Typical Use Case: Timed promotional banners, surveys.

    > on immediate: Triggers immediately after client-side rendering completes without blocking the main thread.
        >>  Typical Use Case: Components that should load right after the page shell.

    > when booleanCondition: Custom signal/boolean expression. When it becomes true, the defer block activates.
        >>  Typical Use Case: Triggering based on user permissions or state store flags.

//////////////////////////////////// SIGNALS ////////////////////////////////////

@ In Angular, Signals are used to manage reactive state and automatically update the UI when that state changes.

@ Signal as a smart variable that tells Angular: “My value changed — update the places that depend on me.”

    > Import signals: import { signal } from '@angular/core'

    > Declare and initiate: count = signal(0)

    > Get: this.count()

    > Set: this.count.set(10)

    > Read-only required input signal [input() / input.required()]: task = input.required<Task>();

    > Modern event emitter: remove = output<string>();

    > Two-way bound signal (parent can bind with [(selected)]="isSelected")

    > Update based on the previous value: this.count.update(value => value + 1): selected = model<boolean>(false);

    > Reactive DOM / component element reference [viewChild() / viewChildren()]: btn = viewChild<ElementRef>('saveBtn')

    > Rerun when dependent signals update: total = computed(() => this.price() * this.quantity());
    
    > Happen whenever a signal changes:   effect(() => { console.log('Name changed:', this.name())});


//////////////////////////////////// ASYNCHRONOUS / REACTIVE PROGRAMMING ////////////////////////////////////

@ The easiest way to understand them is:
    
    >   An Observable represents a stream of values that may arrive over time. 
        >>  Observable = produces data
        >>  subject$.subscribe(value => { console.log('A:', value); }); // manually created 
        >>  this.http.get<User[]>('/api/users').subscribe(users => { this.users = users; }); // http requests return Observables

    >   Subscribe() is how you listen to an Observable. 
        >>  Subscribe = listens to data
        >>  subject$.subscribe(value => { console.log('A:', value); });

    >   A Subject is special because it can act as both an Observable and an Observer. 
        >>  Subject = produces + listens to data
        >>  const subject$ = new Subject<number>(); subject$.subscribe(value => { console.log('A:', value); }); subject$.next(10);
        
    >   a Promise is a standard JavaScript object used to handle a single asynchronous operation. 
        >>  Promise = produces one future result
        >>  const promise = new Promise(resolve => { setTimeout(() => { resolve('Data received'); }, 1000); });


//////////////////////////////////// RXJS ////////////////////////////////////

@ RxJS functions divide into two distinct categories: Creation Functions (which create Observables from various data sources) and Pipeable Operators (which transform, filter, or combine data within a .pipe() chain).

@ Creation Functions:

    > of: Emits the provided arguments in sequence and then completes immediately.
        >>  of(10, 20, 30).subscribe(val => console.log(val)); // Output: 10, 20, 30

    > from: Converts an Array, Promise, Iterable, or Observable-like object into an Observable.
        >>  from([1, 2, 3]).subscribe(val => console.log(val)); // Output: 1, 2, 3

    > fromEvent: Creates an Observable from DOM events or Node EventEmitter events.
        >>  fromEvent(document, 'click').subscribe(event => console.log('Clicked!', event));

    > interval: Emits sequential integers starting at 0 at a specified periodic time interval.
        >>  interval(1000).subscribe(n => console.log(n)); // emits 0, 1, 2... every second and call sub.unsubscribe() to stop

    > timer: Waits for an initial delay, emits 0, and optionally continues emitting sequential numbers at a given interval.
        >>  timer(2000).subscribe(val => console.log('Fired after delay', val)); // Emits 0 after 2 seconds, then completes

    > defer: Creates the Observable lazily only when a subscriber subscribes, allowing dynamic creation per subscriber.
        >>  defer(() => of(Date.now())).subscribe(time => console.log(time));

    > throwError: Creates an Observable that emits no items and immediately emits an error notification.
        >>  throwError(() => new Error('Custom Error')).subscribe({ error: err => console.error(err.message) });

    > EMPTY: An Observable that emits no items and completes immediately.
        >>  EMPTY.subscribe({
                next: () => console.log('Never runs'),
                complete: () => console.log('Completed immediately')
            });

@ Combination Functions & Operators:

    > combineLatest: Combines multiple Observables; whenever any source emits, it outputs the latest value from each source as an array (once all sources have emitted at least once).
        >>  combineLatest([of('Hello'), of('World')]).subscribe(([first, second]) => {
                console.log(`${first} ${second}`);
            }); // Output: Hello World

    > forkJoin: Waits for all source Observables to complete, then emits the last emitted value from each as an array or object (analogous to Promise.all).
        >>  forkJoin({
                user: of({ id: 1, name: 'Alex' }),
                settings: of({ theme: 'dark' })
            }).subscribe(res => console.log(res)); // Output: { user: { id: 1, name: 'Alex' }, settings: { theme: 'dark' } }

    > concat: Subscribes to source Observables sequentially in order; it waits for each to complete before subscribing to the next.
        >>  concat(of(1, 2), of(3, 4)).subscribe(val => console.log(val)); // Output: 1, 2, 3, 4

    > merge: Flattens multiple Observables into a single Observable by forwarding emissions concurrently as they happen.
        >>  merge(of('A', 'B'), of('C', 'D')).subscribe(val => console.log(val)); // // Output: A, B, C, D (order depends on arrival time)

    > zip: Combines values from multiple Observables strictly index-by-index (1st with 1st, 2nd with 2nd).
        >>  zip(of('A', 'B'), of(1, 2)).subscribe(val => console.log(val)); // // Output: ['A', 1], ['B', 2]

    > withLatestFrom: Combines the source value with the latest value from other Observables only when the primary source emits.
        >>  const source$ = of('event');
            const state$ = of('active');
            source$.pipe(withLatestFrom(state$)).subscribe(([evt, st]) => console.log(evt, st));

    > startWith: Emits a specified initial value before emissions from the source Observable begin.
        >>  of(1, 2, 3).pipe(startWith(0)).subscribe(val => console.log(val)); // Output: 0, 1, 2, 3

@ Transformation Operators:

    > map: Applies a projection function to each value emitted by the source Observable.
        >>  of(1, 2, 3).pipe(map(x => x * 10)).subscribe(val => console.log(val)); // Output: 10, 20, 30

    > switchMap: Projects each source value to an inner Observable, cancelling the previous inner Observable execution whenever a new source value arrives.
        >>  of('query1', 'query2').pipe(
                switchMap(q => of(`Result for ${q}`).pipe(delay(100)))
            ).subscribe(res => console.log(res)); // Output: Result for query2 (query1 is cancelled)

    > mergeMap (flatMap): Projects each source value to an inner Observable and merges all inner Observables concurrently without cancelling.
        >>  of('User 1', 'User 2').pipe(
                mergeMap(user => of(`${user} Profile Loaded`))
            ).subscribe(val => console.log(val)); // Output: User 1 Profile Loaded, User 2 Profile Loaded

    > concatMap: Projects each source value to an inner Observable, queuing subsequent inner Observables and running them strictly one after another.
        >>  of(1, 2).pipe(
                concatMap(x => of(`Processed ${x}`).pipe(delay(500)))
            ).subscribe(val => console.log(val));

    > exhaustMap: Projects to an inner Observable and ignores new incoming source values until the current inner Observable completes.
        >>  of('click1', 'click2').pipe( // Useful for preventing double button clicks
                exhaustMap(click => of(`Handled ${click}`).pipe(delay(1000)))
            ).subscribe(val => console.log(val)); // Output: Handled click1 ('click2' is dropped while click1 is active)

    > scan: Accumulates values over time, emitting each intermediate accumulated result (similar to Array.reduce with live emissions).
        >>  of(1, 2, 3).pipe(
                scan((total, n) => total + n, 0)
            ).subscribe(sum => console.log(sum)); // Output: 1, 3, 6
    
    > reduce: Accumulates values over time, but only emits the single final aggregated value once the source completes.
        >>  of(1, 2, 3).pipe(
                reduce((acc, curr) => acc + curr, 0)
            ).subscribe(total => console.log(total)); // Output: 6

@ Filtering Operators:

    > filter: Emits only those items that pass a predicate condition.
        >>  of(1, 2, 3, 4, 5).pipe(
                filter(x => x % 2 === 0)
            ).subscribe(val => console.log(val)); // Output: 2, 4

    > take: Emits only the first specified count of values and then completes.
        >>  of(1, 2, 3, 4).pipe(
                take(2)
            ).subscribe(val => console.log(val)); // Output: 1, 2

    > takeUntil: Emits values from the source until a secondary notifier Observable emits a value, then completes.
        >>  const destroy$ = new Subject<void>();
            interval(1000).pipe(
                takeUntil(destroy$)
            ).subscribe(val => console.log(val));
            // When ready to clean up:
            destroy$.next();
            destroy$.complete();

    > first: Emits only the very first value (or the first value matching a predicate) and then completes.
        >>  of(10, 20, 30).pipe(
                first(x => x > 15)
            ).subscribe(val => console.log(val)); // Output: 20

    > debounceTime: Discards emitted values that take place prior to the expiration of a quiet period between values
        >>  const search$ = new Subject<string>();
            search$.pipe(
                debounceTime(300)
            ).subscribe(query => console.log('Searching for:', query));

    > throttleTime: Emits the first value, then ignores subsequent values for the specified duration.
        >>  const clicks$ = new Subject<string>();
            clicks$.pipe(
                throttleTime(1000)
            ).subscribe(evt => console.log('Click registered:', evt));

    > distinctUntilChanged: Suppresses duplicate consecutive items emitted by the source.
        >>  of(1, 1, 2, 2, 3, 1).pipe(
                distinctUntilChanged()
            ).subscribe(val => console.log(val)); // Output: 1, 2, 3, 1

@ Utility & Error Handling Operators:

    > tap: Performs side effects (logging, debugging) on emissions without altering the data stream.
        >>  of(5).pipe(
                tap(n => console.log('Incoming:', n)),
                map(n => n * 2),
                tap(n => console.log('Outgoing:', n))
            ).subscribe(); // Output: Incoming: 5, Outgoing: 10

    > catchError: Catches errors on the source Observable and returns a replacement Observable or throws a processed error.
        >>  throwError(() => new Error('Server Down')).pipe(
                catchError(err => of('Fallback Cache Data'))
            ).subscribe(data => console.log(data)); // Output: Fallback Cache Data

    > retry: Resubscribes to the source Observable if an error occurs, up to a specified count.
        >>  let attempts = 0;
            of(null).pipe(
                mergeMap(() => {
                    if (++attempts < 3) return throwError(() => new Error('Temporary failure'));
                    return of('Success on retry!');
                }),
                retry(2)
            ).subscribe(val => console.log(val)); // Output: Success on retry!

    > finalize: Executes a callback function when the Observable terminates (either completes or errors).
        >>  of(1, 2).pipe(
                finalize(() => console.log('Stream ended - cleaning up'))
            ).subscribe(val => console.log(val)); // Output: 1, 2, Stream ended - cleaning up

    > shareReplay: shares one Observable execution between multiple subscribers and replays previously emitted values to new subscribers.
        >>  const numbers$ = of(10, 20, 30).pipe(
                shareReplay(1) // Remember/replay the latest 1 emitted value.
            );
            numbers$.subscribe(value => {
                console.log('First:', value);
            }); 


//////////////////////////////////// NGRX SIGNAL STORE ////////////////////////////////////

@ Think of NgRx with Signals (specifically the NgRx SignalStore) as a direct upgrade to the old way of handling state in Angular.

@ NgRx SignalStore replaces traditional, complex NgRx boilerplate with a lightweight system. Powered by Angular Signals, it combines state, computed values, and async logic into a single, high-performance file with zero boilerplate.

@ Steps to set, handle and compute the data in global store:
    > Create the store file: 
        >>  ./cart.store.ts

    > Import necessary methods: 
        >>  import { signalStore, withState, withComputed, withMethods, withHooks, patchState } from '@ngrx/signals';
        >>  import { withEntities, addEntity, updateEntity, removeEntity, setAllEntities } from '@ngrx/signals/entities';

    > Initialize the interface: 
        >>  interface CartState { isLoading: boolean, couponCode: string, items: any } // for state management
        >>  interface Photo  { id: number, title: string, url: string } // for entities management

    > Declare the initial state value: 
        >>  const initialCartState: CartState = { isLoading: false, couponCode: null, items: [] }

    > Let's build the store: 
        >>  export const CartStore = signalStore({ providedIn: 'root' }, withState(),...);

    > Can be root-level singleton or component-scoped (if needed): 
        >>  { providedIn: 'root' }

    > Initialize the state by passing value: 
        >>  withState(initialCartState)

    > Initialize the entities by passing the type (if needed)
        >>  withEntities<Photo>()

    > To add extra properties/dependencies to the store (if needed):
        >>  withProps(() => ({
                photoService: inject(PhotoService)
            }))

    > Derived / Computed Values (auto-recalculated only when items change):
        >>  withComputed((store) => ({
                totalCount: computed(() => store.items().reduce((sum, item) => sum + item.quantity, 0)),
            })),

    > Methods (State Mutators & Async Calls):
        >>  withMethods((store, cartApi = inject(CartApiService)) => ({
                applyCoupon(code: string): void {
                    // patchState() is an NgRx Signal Store utility used to update/modify the state.
                    patchState(store, { couponCode: code });
                },

                // Reactive / Async API call using rxMethod and import it from '@ngrx/signals/rxjs-interop' (if needed)
                loadCart: rxMethod<void>(
                    pipe(
                        tap(() => patchState(store, { isLoading: true })),
                        switchMap(() => cartApi.fetchCart()),
                        tap((items) => patchState(store, { items, isLoading: false }))
                    )
                ),
            })),

    > Use lifecycle hooks in store (if needed):
        >>  withHooks({
                onInit(store) {
                    store.loadCart(); // Auto-fetch cart on app start
                },
            })

@ Entity Management is used when your state contains a collection of similar objects, such as users, products, photos, orders, etc.

@ List entity management methods:
    > withEntities<Entity>(): Adds normalized entity state (entityMap, ids, and an entities() computed signal) to the store.
        >>  withEntities<Photo>()

    > setAllEntities(entities, config?): State updater function for patchState that replaces the entire entity collection with a new array.
        >>  patchState(store, setAllEntities(photos));

    > setEntities(entities, config?): Merges or inserts this batch array without deleting existing stored items
        >>  patchState(store, setEntities(newPhotos));

    > setEntity(entity, config?): State updater function that adds or replaces a single entity.
        >>  patchState(store, setEntity(newPhoto));

    > addEntities(entities, config?): State updater function that inserts multiple new entities into the collection without updating existing ones.
        >>  patchState(store, addEntities(newPhotos));

    > addEntity(entity, config?): State updater function that inserts a single new entity.
        >>  patchState(store, addEntity(newPhoto));

    > updateEntities(updates, config?): State updater function that applies partial updates to multiple existing entities.
        >>  patchState( store, updateEntities({ id, changes: { title } }));

    > updateEntity(update, config?): State updater function that applies a partial update to a single existing entity.
        >>  patchState( store, updateEntity({ id, changes: { title } }));

    > removeEntities(ids, config?): State updater function that deletes multiple entities from the collection by their IDs.
        >>  patchState(store, removeEntities(id));

    > removeEntity(id, config?): State updater function that deletes a single entity by its ID.
        >>  patchState(store, removeEntity(id));

    > removeAllEntities(config?): State updater function that clears all entities and IDs from the store.
        >>  patchState(store, removeAllEntities());

    > entities() or allEntities(): An array of all entity objects.
        >>  this.store.entities();

    > entityMap(): pull a single item out of the store efficiently, use store.entityMap() instead of looping through an array
        >>  this.store.entityMap()[todoId]; // Returns the Todo object or undefined

    > ids(): An array of just the primary keys and helps us to count the array length
        >>  this.store.ids()
        >>  this.store.ids().length
